# The front light controls the rear as an ANT+ Bike Lights controller

Without a bike computer the rear light should follow the front light, and with one, the bike computer should still see and switch both. The front light therefore opens a second ANT channel (a slave) and sends the rear the same light settings command (page 34) that a Wahoo sends. It takes the **controller role of the existing ANT+ Bike Lights profile** instead of a custom profile or a light network. The rear is unchanged: it cannot tell the front from a bike computer, and it does not need to (ANT-14).

- **Priority by rule, not by device class.** The front relays only changes the rider made at the front (button, wake, boot). Two controllers never fight: the last change wins. A bike computer can override the rear at any time, and its commands to the front are not copied to the rear, because it commands the rear itself. A hard priority ("the front stops while a bike computer is connected") was rejected, because it loses the case where the rider switches both lights from the front while the bike computer only watches.
- **No connect.** The front addresses "all taillights" with light index 0 and never sends page 33, so it never takes the rear's light index and a bike computer's connection to the rear stays intact. Without the shared channel (ANT-6) this is also the only way two controllers can address the same light.
- **Nearest taillight each wake.** The rear is found by proximity search and accepted only if its page 1 says taillight; other lights go on the exclusion list. No setup and no flash storage, but a stranger's taillight closer than the own rear at the moment of the search can be picked. Measured on the bench, the signal strength barely separates the distances indoors (median -62 dBm at mounting distance, -69 at 5-10 m), so the threshold (-75 dBm, set in dBm because the nRF51 proximity bins were too strict for these boards) mainly finds the own rear reliably and keeps out lights further away. A stored pairing (button gesture plus flash) is the upgrade if a stranger's light gets picked in practice. Once found, ANT keeps the device ID for the rest of the wake.
- **Off before sleep, but not on a flat battery.** The front's power-off sends Off to the rear and waits for the acknowledgement (at most 1.5 s) before closing the channels. The rear then stays awake and dark until the front, a bike computer or its own button switches it on. The critical battery cut-off of the front does not relay Off: a dead front battery must not darken the rear.
- **Delivered means applied, not acknowledged.** On the bench (R4) the rear acknowledged a command that arrived within its stable window after its own wake press and ignored it, so the front believed it was delivered. The front now waits until the rear's page 1 reports the commanded mode and sends again after the window. This needs no change on the rear, and it also covers a command lost for any other reason. The price: a change at the rear's button or by a bike computer in those few seconds is overridden.
- **The stable window protects button presses only.** On the bench, a second front press within 3 s reached the rear only through the resend, because the rear's stable window (ANT-8) was started by every state change, also by the front's previous command. The window now starts only on changes made at the light itself; `STABLE_WINDOW_LOCAL_ONLY` 0 restores the earlier rule if the quick succession of commands turns out to be unwanted. The resend stays for the case it was built for: a command right after a press on the rear's own button.
- **Bench result (Nov 2026).** The front found the rear within seconds; Off, Smart, Steady and Flash were acknowledged, the Off before sleep after one retry.
