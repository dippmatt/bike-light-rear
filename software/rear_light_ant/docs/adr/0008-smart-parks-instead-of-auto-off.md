# Smart parks on a stationary timeout instead of powering off

After the stationary timeout (ADR-0002) Smart no longer powers off. It parks: main LED and light sensor off, the status LED pulses 30 ms every 5 s, and the LIS3DH runs only its own motion detector (low-power 10 Hz, high-pass filter, threshold on any axis, latched in `INT1_SRC`). Motion returns the light to normal Smart by itself, so the rider no longer has to press the button after a stop. Parking is a phase of the Smart state, not a state: button rules, the Selection Window and the ANT+ report (Auto) are unchanged.

- **Polled latch, not an interrupt.** The LIS3DH INT1/INT2 pins have no net on the board, so the MCU polls the latched flag every second. The latch means motion between two polls is not lost. Software comparison of slow samples was rejected because it misses short movements between samples. Wiring INT1 to a GPIO would allow a true interrupt wake and needs a board revision.
- **The ANT channel stays open.** The bike computer keeps seeing the light as Auto and can still switch it. This costs the ANT broadcast current all the time while parked. Closing the channel was rejected because the light would disappear from the bike computer.
- **No park timeout.** A light parked for days keeps the ANT broadcast and the accelerometer running until the critical battery cut-off powers it off (BAT-3). This drain is accepted in exchange for always waking on motion. Revisit this if parked current measurements show a short standby time.
- **Smart Auto-Off is kept.** The earlier behaviour (power off at the stationary timeout) remains as its own state, outside the Mode Cycle. Putting `LED_SMART_AUTO_OFF` in place of `LED_SMART` in `mode_cycle` (`src/sm.c`) restores the old light; an ANT+ Auto request follows the Smart variant in the cycle.
- **Fail-safe.** If the motion detector cannot be set up, Smart keeps normal sampling instead of parking, so the light never sits dark without a wake source.
