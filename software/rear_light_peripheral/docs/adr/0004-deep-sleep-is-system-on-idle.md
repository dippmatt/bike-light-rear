# Deep Sleep is System ON idle, not System OFF

Deep Sleep stops all outputs, sensors, battery sampling and BLE advertising and lets the CPU idle in System ON until the button's level interrupt (or the USB poll) wakes it. It does not use nRF System OFF. On real hardware the device sometimes did not wake again from System OFF: a debugger attach woke it (so it was asleep), but neither the button nor USB power did, and only a reset or battery removal recovered it. The cause was never found. System ON keeps the normal interrupt path as the wake source, needs no reset on wake, and costs a few µA more than System OFF. Do not switch back to System OFF without reproducing and fixing that failure first. The wake interrupt uses the level-active SENSE/PORT mechanism (no GPIOTE channel) to keep the sleep current low.
